我在 macOS 上验不了的三件事

下面的步骤里大部分我已经在本机的 wezterm 上跑通了。但有三块只能靠你这边确认， 验收时重点看这几步：

  • credman.ps1 从没被执行过 —— 这台 Mac 没有 PowerShell。逻辑是照 keytar 源码写的， 但一行都没跑过。Step 5 就是专门验它的。
  • 真实的 Windows ssh.exe —— 算法过滤是拿 macOS 的 OpenSSH 10.3 验的， 你那边版本不同，能留下的算法会不一样（这是设计如此）。Step 4 验它。
  • Windows 上的 Rust TUI 原生产物 —— CI 会在 macOS arm64/x64 和 Windows x64 分别构建；Windows 仍需在真实 WezTerm 中验证 resize、中文宽度、键鼠和 SFTP。 Step 8 验它。
00分支点

确认你是哪种安装方式

推荐直接从公开仓库安装。wezterm.plugin.require 会把仓库 clone 到 wezterm 自己的插件目录并从该副本加载；不需要 GitHub 登录或在 URL 中附加凭据。 按 Ctrl+Shift+L 打开 debug overlay：

debug overlay
wezterm.plugin.list()

路线 A · 公开 URL（推荐）

你用的是 plugin.require。列表里应该有 https://github.com/stabey/wezterm-ssh-manager。

更新运行 update_all()，然后重新加载配置。

路线 B · 本地开发

你用的是 package.path + require，直接从自己的开发 checkout 加载。

在该 checkout 运行 git pull 后按 Ctrl+Shift+R，跳过 Step 2。

注意

如果这一步就报 could not find repository at ...plugins\xxx， 说明插件目录里混进了一个非 git 目录（多半是某次失败 clone 留下的）。 wezterm.plugin.list() 会对每个子目录 Repository::open， 一个失败就整体报错。把那个目录删掉再来。

01

配置公开安装源

wezterm.lua
local sshmgr = wezterm.plugin.require(
  'https://github.com/stabey/wezterm-ssh-manager'
)
sshmgr.apply_to_config(config)
期望

重载配置后，wezterm.plugin.list() 显示上述公开仓库 URL。

失败

拉不下来时先确认可以访问 GitHub，并检查 URL 是否完整。公开仓库不需要认证， 不要在 URL 中嵌入用户名、访问令牌或其他凭据。

让 wezterm 同步到副本

debug overlay 里跑：

wezterm.plugin.update_all(); wezterm.reload_configuration()
注意

update_all() 把错误吞进日志，不会抛给你 （源码里是 Err => log::error!），所以它"没反应"和"成功了"看起来一样。 真正的确认在下一步。

失败

Step 3 验不过的话，最省事的办法是直接删掉 %APPDATA%\wezterm\plugins\ 下由 wezterm.plugin.list() 显示的对应插件目录，重启 wezterm 会重新 clone。

04

验算法过滤

这是修 pane 闪退的那个。挑一个 Tabby 转过来、算法列表最长的 profile：

debug overlay
wezterm.plugin.require(
  'https://github.com/stabey/wezterm-ssh-manager'
)
  .command_for '你的profile名'
期望

输出的命令行里不再出现 arcfour、blowfish-cbc、 cast128-cbc、不带 @openssh.com 的 aes128-gcm、 hmac-ripemd160、ext-info-c、kex-strict-。

3des-cbc、ssh-rsa、hmac-md5 这些应该还在 —— 它们是遗留但你的客户端支持，留着才连得上老设备。

真正的证明

把上面输出的命令复制到普通 pwsh 标签页，ssh 后面加 -G：

PowerShell
ssh -G -o Ciphers=... -o MACs=... 你的主机 > $null
$LASTEXITCODE
期望

0。-G 只解析配置不连网，所以这是纯粹的参数合法性检查。

失败

255 = 还有名字没被过滤掉。日志里搜 does not support 看它到底剔了什么、剩了什么，把结果发我。

附带

日志里应该有若干行 [ssh-manager] <profile>: ssh.exe does not support ...; dropped from Ciphers。 没有任何这种行，而 Step 3 又过了，说明这些 profile 的算法列表本来就是干净的 —— 也正常。

05未验证

验凭据管理器取密码

这段代码一次都没跑过，重点看。先列出凭据管理器里有什么 —— 只打印 target 和用户名，不打印密码：

如果还没有源码 checkout，先从公开仓库 clone 一份供下面的辅助脚本使用：

PowerShell
git clone https://github.com/stabey/wezterm-ssh-manager `
  "$env:USERPROFILE\src\wezterm-ssh-manager"
PowerShell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$env:USERPROFILE\src\wezterm-ssh-manager\tools\credman.ps1" -List
期望

一堆 ssh@主机 或 ssh@主机:端口 开头的 target， User 列是你的登录名。数量应该和 Tabby 里配了密码的 profile 数对得上。

空的

报 no credentials match 'ssh@*' = 你在 Tabby 里开了 Vault。 密码是 AES 加密存在 config.yaml 的 vault.contents 里， 读不出来。先去 Tabby 里关掉 Vault（它会把 secret 写回凭据管理器）， 再回到这一步。

报错

Add-Type 或 CredRead 相关的报错 = 我写的 P/Invoke 有问题。 把完整报错发我，这是我改代码而不是你改环境。

读一条真的

PowerShell
powershell -NoProfile -ExecutionPolicy Bypass `
  -File "$env:USERPROFILE\src\wezterm-ssh-manager\tools\credman.ps1" `
  -Target 'ssh@某主机:22/某用户'
期望

原样打印出密码，没有结尾换行，和你在 Tabby 里存的一致。

乱码

出现方块字或乱码 = 编码判断错了。keytar 存的是密码的 UTF-8 原始字节， 不是 Windows 惯例的 UTF-16LE，脚本按 UTF-8 解并靠交替 NUL 字节识别 UTF-16。 乱码说明这个判断在你的数据上不成立，告诉我。

06破坏性

重新跑 Tabby 转换

先备份

转换覆盖整个文件，是从 Tabby 的 config.yaml 重新生成的。 你在面板里加过、但 Tabby 里没有的 profile 会消失。 Step 5 没过就先别做这一步 —— 没有密码钩子的话转了也是白转。

PowerShell
Copy-Item C:\Users\你\.config\wezterm\ssh_profiles.lua `
          C:\Users\你\.config\wezterm\ssh_profiles.lua.bak2
debug overlay
wezterm.plugin.require(
  'https://github.com/stabey/wezterm-ssh-manager'
).export_tabby {
  to = 'C:/Users/你/.config/wezterm/ssh_profiles.lua',
  force = true,
}
期望

返回 true 和一行统计，形如 N profile(s) -> C:/... (M skipped, P password hook(s), R regex(es) need review)。

password hook(s) 的数量应该和 Step 5 -List 出来的条数对得上。

路径

to 一定要写全。不写的话默认是 wezterm.config_dir —— 如果你的配置是 %USERPROFILE%\.wezterm.lua，那 config_dir 就是 %USERPROFILE%，文件会掉在用户根目录。

07

检查生成的文件

先看文件头的迁移报告，再用 grep 确认没有漏网的：

PowerShell
# 应该一条都搜不到
Select-String -Path C:\Users\你\.config\wezterm\ssh_profiles.lua `
  -Pattern 'arcfour|blowfish-cbc|cast128-cbc|ext-info-|kex-strict-|hmac-ripemd160'

# 密码钩子的数量
(Select-String -Path C:\Users\你\.config\wezterm\ssh_profiles.lua `
  -Pattern 'password_cmd').Count

# 脚本被拷到同目录了吗
Test-Path C:\Users\你\.config\wezterm\credman.ps1
期望

第一条无输出；第二条等于密码 profile 数；第三条 True。

文件头应该有 ALGORITHMS DROPPED 和 PASSWORDS 两段， PASSWORDS 里每行是 <profile 名> ssh@主机:端口/用户名。

检查

PASSWORDS 段里的 target 要带端口（没写就 :22）。Tabby 的 yaml 常常省略默认端口，但凭据管理器里的条目 是带端口的。转换器按「没写 = 22」拼 target，再删掉冗余的 port = 22。

真实连接 + SSH Manager TUI

密码认证的服务器

Ctrl+Shift+S 打开 SSH Manager tab，左边选分组，右边回车连一个 auth: password 的。Manager 应留着，SSH 在新 tab。

期望

自动填密码登录，不弹密码提示。日志里能看到 [ssh-manager] <名字>: sent <hidden> —— 密码永远不会明文进日志。

卡在密码提示

说明 password_cmd 没取到值。手动跑一遍 Step 5 的 -Target 命令， target 用文件头 PASSWORDS 段里那个，看是命令本身的问题还是 target 对不上。

pane 一闪就关

算法还有问题，回 Step 4。

跳板机的服务器

挑一个配了 jumpHost 的，确认 -J 那一跳能过。

TUI 管理

还在 Manager tab 里走一遍：n 新建 → e 改几个常用字段 → d 删掉。 再按一次 Ctrl+Shift+S 应切回同一个 tab，不要再开一个。

默认后端是 Rust TUI。仓库里有本平台的 tui-rust/dist/sshmgr-tui-* Actions/Release 产物或 tui-rust/target/release/sshmgr-tui[.exe] 本机构建时优先使用；否则依次 回退 OpenTUI/Bun 和 Python Textual。编辑表单目前只显示名称、分组、目标、认证和跳板机等 常用字段，未显示的高级字段会原样保留。

SFTP 双栏

在 Manager 选中主机后按 s，确认左侧本地目录、右侧远端目录能读取。 走一遍新建目录、普通文件上传、改名、下载、删除；再用 c 取消一次进行中的传输。 密码 profile 会在新建 SFTP 会话时重新询问，私钥、Agent 和单跳跳板机应自动映射。

期望

保存后列表刷新，不用重启 TUI。 ssh_profiles.lua 的文件头注释原样保留。 snapshot JSON 里没有明文 password。

前提

TUI 默认编辑 <wezterm 配置目录>/ssh_profiles.lua。 想让它编辑别的文件，在 apply_to_config 里加 profile_store = 'C:/.../ssh_profiles.lua'。 改完没生效，先查这个。

回滚

退回去

三样东西可以独立回滚，互不影响：

PowerShell
# 1. profile 文件 —— 用备份
Copy-Item C:\Users\你\.config\wezterm\ssh_profiles.lua.bak `
          C:\Users\你\.config\wezterm\ssh_profiles.lua

# 2. 本地开发 checkout —— 回到一个已发布版本（仅路线 B）
git -C "$env:USERPROFILE\src\wezterm-ssh-manager" fetch --tags
git -C "$env:USERPROFILE\src\wezterm-ssh-manager" checkout v1.0.0

# 3. 插件 checkout 彻底重置
# 先用 wezterm.plugin.list() 确认精确路径，再删除对应目录；重启后会重新 clone。

路线 B 执行第 2 项后按 Ctrl+Shift+R 重新加载本地代码。 路线 A 要恢复公开仓库当前版本时执行第 3 项，重启 wezterm 后会自动重新 clone。
